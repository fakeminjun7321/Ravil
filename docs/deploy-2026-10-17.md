프로젝트 데스크, 소개·로그인 화면, 프로젝트 범위의 계획 처리와 일정 파일 수정을 반영했다. Worker를 먼저 배포한 후 Pages를 반영했다. `--keep-vars --strict`를 사용했고, D1/R2 바인딩과 기존 시크릿 바인딩 메타데이터·허용 origin 설정이 배포 전후 일치한다. 시크릿 값은 조회하지 않았다.

기존 데이터베이스에서 필요한 테이블 15개가 모두 존재하는 것을 확인했다. 마이그레이션 추적 목록은 기존 직접 적용된 스키마와 달랐지만, 실제 테이블을 대조해 SQL 마이그레이션을 추가 실행하지 않았다. DNS·도메인·요금제·결제 설정은 변경하지 않았다. Mac 네이티브 앱의 기존 변경 사항은 이번 배포 대상이 아니다.

## 운영 요청 수와 결과

의도적인 직접 HTTP 요청 **3회**, 브라우저 상위 화면 이동 **2회**, 합계 **5회**였다. 자동 세션 확인·정적 자산 로딩·로그인 리다이렉트의 개별 네트워크 요청 수를 모두 계측한 것은 아니다. Cloudflare 관리 API와 D1 스키마 읽기는 위 사이트 요청 수와 별도이다.

1. `GET https://ravil.app/` → 200. HTML SHA-256 `13c58ef5a2c1b92f956a6af5607de64f92d97d0628a0e388f09e68ff785b031a`, 로컬 배포 빌드와 일치.
2. `GET https://ravil.app/api/health` → 200, `{"service":"RAVIL workspace","version":1}`. Pages → Worker 서비스 연결의 이 상태 경로를 확인했다.
3. `GET https://www.ravil.app/` → 308, Location `https://ravil.app/`.
4. Chrome에서 ravil.app 진입 → 새 소개 화면·기록 입력·작업 진입 링크 확인.
5. ‘내 작업 열기’ 클릭 → `https://ravil.app/login/?next=%2Fworkspace%2F`, 새 로그인 폼 확인.

직접 HTTP 요청은 순차 실행했고 각 주소를 한 번씩만 조회했다. 자동 재시도나 부하 검사는 수행하지 않았다. 배포 전후 62개 소스 파일의 해시를 대조해 승인한 소스가 유지되는 것도 확인했다.
