# Ravil-ASMR 로컬 전사 최적화 기록 · 2026-09-30

후속 개발: [0.4 긴 녹음·한국어/영어 처리 기록](ravil-asmr-0.4-development.md). 아래는 0.2/0.3 실험 당시의 결과와 한계다.

2026-10-01 후속: [0.5 경량·영어 고속 후보 실측](ravil-asmr-0.5-development.md), [모델·연구 및 dot 실행 환경 조사](asr-research-2026-10-01.md).

## 판단

현재까지의 **실험 후보**는 Qwen3-ASR 1.7B의 4비트 또는 6비트 MLX + Qwen ForcedAligner 0.6B 4비트다. 단순히 큰 공개 모델을 붙인 것이 아니라, Ravil이 5분 이하 음성의 전사·단어 정렬·시각 검사·구간 묶기·출처 기록을 한 로컬 경로로 조합했다. 가중치 자체는 공개 모델의 변환본이며 Ravil 고유 학습 가중치라고 부르지 않는다. [4비트 모델 카드](../config/ravil-asmr-0.2-MODEL_CARD.md)와 [6비트 모델 카드](../config/ravil-asmr-0.3-MODEL_CARD.md)에 원본·변환본의 출처·리비전·해시·라이선스를 기록했다.

## 같은 음성에서의 크기·품질·속도

FLEURS 한국어 test 100문장, 정규화된 4,667자. 각 모델이 같은 오디오 목록을 처리했다. 측정 기기는 이 Mac(Apple M5, 통합 메모리 24GB)이다.

| 경로 | 가중치 | 문자 오류율 | 측정한 100문장 추론 시간 합 |
|---|---:|---:|---:|
| 기존 Ravil Whisper Turbo q5_0 | 574MB | 4.09% (191오류) | 108.9초 |
| Qwen3-ASR 1.7B PyTorch MPS | 4.08GB | 3.17% (148오류) | 277.9초 |
| Qwen3-ASR 1.7B 4비트 MLX | 1.60GB | 3.71% (173오류) | 75.8초 |
| Qwen3-ASR 1.7B 6비트 MLX | 2.03GB | 3.30% (154오류) | 79.5초 |

4비트는 원본 Qwen보다 25글자 더 틀렸지만 가중치가 약 2.5배 작고 추론 시간 합이 약 3.7배 짧았다. 6비트는 4비트보다 가중치가 약 430MB 늘고 시간 합은 약 5% 늘면서, 추가 오류 25글자 중 19글자를 회복했다. 이 Mac에서는 **6비트가 정확도·속도의 균형 후보**, 4비트가 용량 우선 후보로 보인다. Qwen 두 실행 방식은 모델을 한 번 로드해 연속 실행했고 Turbo는 각 문장에서 새 프로세스를 띄웠으므로, 이 시간 합만으로 앱의 체감 지연·배터리 우위를 확정하지 않는다. 4비트의 로드 후 활성 메모리는 약 1.61GB, 평가 중 최대 약 2.70GB였다. 6비트는 약 2.04GB와 3.13GB였다. 공개 **읽기 음성** 결과이며 실수업·혼합 언어의 우위는 미검증이다.

## 타임스탬프를 포함한 2단계 경로

MLX ASR 단독으로는 실제 20초 녹음에 0~20초 구간 하나가 나왔다. 출처 시점 이동에 충분하지 않아 [MLX 4비트 ForcedAligner](https://huggingface.co/mlx-community/Qwen3-ForcedAligner-0.6B-4bit)를 추가했다. 두 모델의 가중치 합은 약 2.57GB다. 함께 로드한 활성 메모리는 약 2.59GB, 합성 23.56초 음성 처리의 최대 활성 메모리는 약 3.66GB였다. 합성 음성의 실제 발화가 약 10~13초일 때 한국어 여섯 단어의 정렬 시각은 10.0~13.36초에 분포했다. 한 번 준비된 정렬 모델은 전체 23.56초에서 약 0.22초, 발화 구간만 자른 3.7초에서 약 0.10초였다. 이 비교는 같은 프로세스의 따뜻한 호출이며 일반적인 첫 실행 시간은 아니다.

사용자가 로컬 사용을 허락한 현물·국어·영어 녹음의 20초 클립 세 개에서 ASR과 정렬을 실행했다. 각각 3·4·6개 구간이 나왔고 Ravil의 `WhisperOutput`/`RecognizedPhrase` 디코더가 모두 읽었다. 120초 현물 클립에서는 모델 로드 1.35초, 전사 10.87초, 정렬 2.00초, 최대 활성 메모리 약 4.26GB, 단어 203개·구간 16개였다. 실제 문장 및 단어 시각의 정답성은 사람이 검수하지 않았다. 현재 실험 코드는 5분 이하 모노 16kHz PCM WAV만 받으며 앱 설치판의 버튼·저장 흐름에 연결돼 있지 않다.

같은 120초 현물 클립을 **6비트 ASR + 4비트 정렬**로 다시 처리하자 모델 로드 1.13초, 전사 9.72초, 정렬 1.51초, 최대 활성 메모리 약 4.69GB, 단어 196개·구간 16개였다. Ravil의 JSON 계약을 통과했다. 두 실행의 단어 수 차이는 정답이 없으므로 정확도 개선이나 악화로 판정할 수 없다.

`script/transcribe_mlx_qwen_aligned.py`는 빈 전사·치환 문자·역전/범위 밖 시각과 원문과 크게 다른 정렬문을 저장 전에 거부한다. 120초 결과를 Ravil 실행 파일의 `--transcription-contract-check`로 다시 읽어 16구간이 수락되는 것을 확인했다. 검수된 단어별 시각 정답이나 5분 초과 연속 녹음에 대한 검사는 아직 없다.

## Alt 분석과 VAD 실험

[Alt 경쟁 경로 분석](alt-stt-competitive-analysis.md)은 설치 자산·제품 공개 설명·선행연구를 분리한다. 확인된 자산은 공개 Whisper Turbo q5, Core ML 인코더, Silero VAD이고, 제품 사이트는 MLX 디코더와 화자 분리를 설명한다. 특정 수업에서 실제로 실행된 설정은 확인되지 않았다. [WhisperX 연구](https://arxiv.org/abs/2303.00747)는 긴 녹음에서 VAD 분할과 강제 정렬의 가치를 제시한다.

Ravil 기존 Homebrew 복사 번들은 Homebrew GGML 플러그인을 우선 읽는 상태에서 VAD를 켜면 종료 신호 11로 충돌했다. `script/build_whisper_runtime.sh`는 고정된 공개 `whisper.cpp` 소스를 빌드하고 플러그인을 실행 파일 옆에 둔 독립 번들을 만든다. 격리된 Ravil 앱의 헤드리스 VAD 전사와 Homebrew 읽기 차단 검사를 통과했다. 기존 설치 앱과 DMG는 교체하지 않았다.

마지막 격리 앱 빌드는 `swift build -c release`와 `codesign --verify --deep --strict`, Homebrew 읽기 차단 상태의 `--transcription-check ... ko --vad`, 120초 Qwen 구간 JSON 계약 검사, `--smoke-test`를 통과했다. 이는 앱을 전경에서 조작한 녹음→전사→저장 경로의 증거가 아니다. `script/package_dmg.sh`는 VAD 파일 해시·고지문·런타임 리비전이 없거나 다르면 포장을 거부한다.

VAD 없는 합성 음성의 시각은 0~13.24초, VAD를 사용하면 실제 발화에 가까운 9.99~13.19초였다. 그러나 FLEURS 짧은 20문장은 VAD 없이 13글자 오류, VAD 사용 시 19글자 오류였고 21.75초 → 23.08초로 느려졌다. 120초 실제 녹음은 VAD 없이 8.02초, VAD 사용 시 6.26초였으나 검수 정답이 없어 16글자 적은 출력이 무음 환각 제거인지 발화 누락인지 판단할 수 없다. VAD는 기본값으로 켜지 않고 긴 녹음·무음 비율이 높은 구간에서 추가로 시험한다.

## 다음 개발 기준

1. 검수된 실제 강의 구간으로 과목 용어 CER, 누락, 무음 환각, 단어 시각 오차와 화자 전환을 측정한다. Alt 기존 전사나 여러 모델의 다수결을 사람 정답으로 바꾸지 않는다.
2. 5분을 넘는 녹음을 VAD로 안전하게 분할하고 경계 중복·문장 누락을 검증한다. 4비트 정렬 모델의 긴 수업 메모리·배터리·저장 용량을 재측정한다.
3. Qwen/MLX 실행 파일과 모델을 설치 앱에서 자체 관리하거나 적절한 Swift 런타임으로 옮긴다. 현재 Python 가상환경에 의존하는 프로토타입은 배포 경로가 아니다.
4. 학습지에서 나온 과목 용어는 출처와 사용자가 검수한 목록으로 관리해 문맥 프롬프트의 전후 차이를 평가한다. 학교 자료를 공개 가중치의 학습 데이터로 쓰기 전에는 권리와 동의를 별도로 확인한다.

실험 의존성은 `config/model-opt-requirements.txt`에 고정했다. 공개 Whisper 모델과 VAD는 각각 `script/fetch_local_model.sh`, `script/fetch_local_vad.sh`로 해시 확인 후 받는다. `script/build_whisper_runtime.sh`는 `RAVIL_CMAKE`와 필요시 `RAVIL_WHISPER_SOURCE_DIR`·`RAVIL_WHISPER_BUILD_DIR`·`RAVIL_WHISPER_RUNTIME_DIR`을 받아 격리 빌드를 만든다. 그 런타임을 앱에 실험적으로 묶을 때만 `RAVIL_WHISPER_RUNTIME_DIR=<검증된 패키지>`를 `script/build_and_run.sh --build`에 전달한다. 기본 배포 경로는 아직 바꾸지 않았다.

[MLX Audio Swift](https://github.com/Blaizzy/mlx-audio-swift) 커밋 `b7c7971d94c4f73de910797593851d00858daf19`의 격리 CLI도 시험했다. 처음 계산된 최신 `swift-collections 1.7.1`은 이 도구 구성에서 표준 라이브러리 타입 오류가 났다. 프로젝트의 `Package.resolved`에 있는 1.3.0으로 다시 고정한 뒤에는 **Metal 컴파일러 `metal` 부재**로 빌드가 멈췄다. 이 Mac은 Command Line Tools만 선택돼 있고 Xcode는 확인되지 않았다. 앱의 SwiftPM 의존성은 추가하지 않았으며, 네이티브 이식의 실행·성능은 미검증이다.

사용 허가된 학습지는 `script/extract_material_terms.py`로 최신 판본의 텍스트층과 승인된 OCR만 읽어 과목별 용어 **후보**를 비공개 생성했다. 현물 178쪽, 천문 33쪽, 영어 43쪽의 텍스트를 읽을 수 있었고 국어는 해당 자료에서 사용 가능한 검수 텍스트가 0쪽이었다. 현물 후보에는 반복 머리말·저작권 문구가 여전히 섞여 있어 자동 전사 프롬프트나 모델 학습에 주입하지 않는다.
