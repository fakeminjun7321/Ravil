# Ravil 퀴즈·Codex 연결 설계 메모 (2026-09-25)

이 문서는 사용자 요청을 바탕으로 한 다음 단계의 설계다. 퀴즈 생성·복습 UI, Codex 로그인·호출, 결제는 아직 구현하지 않았다.

2026-09-25 결정: Codex 연결 방식은 아래의 **Ravil 내부 App Server 클라이언트**로 잡되, 실제 구현은 사용자가 요청한 대로 뒤로 미루고 관련 기능을 한 번에 진행한다. 지금은 로그인·대화 패널·Codex 런타임을 앱에 추가하지 않는다.

## Anki에서 가져올 것과 바꿀 것

사용자가 불편하다고 한 `1분 후`, `4분 후` 표시는 Anki의 학습 단계/다음 복습 간격을 뜻하며 macOS 알림을 뜻하는 것은 아니다. 공식 매뉴얼은 `Again` 또는 `Good` 응답에 따라 짧은 학습 단계로 카드가 다시 나타날 수 있다고 설명한다. 시험 범위를 특정해 훑는 기능은 Anki에도 필터 덱/Custom Study로 있으나, 일반 복습 화면의 기본 우선순위와는 목적이 다르다.

Ravil의 기본 퀴즈는 **중간고사 범위 커버리지 우선**으로 설계한다.

1. 세션을 시작할 때 과목·자료·단원·남은 시간을 선택하고, 현재 판본에서 확인된 문항만 모은다. OCR이 없는 자료는 자동 문제 생성에서 제외하거나 `근거 확인 필요`로 표시한다.
2. 첫 순회에서는 새 범위와 아직 보지 않은 개념을 먼저 보여 준다. 방금 틀린 문제를 1~4분 뒤에 끼워 넣어 다른 범위를 가리지 않는다.
3. 틀림·헷갈림·맞음 평가는 기록하되, 틀린 문제는 첫 순회가 끝난 뒤 `약점 다시 보기` 묶음에 넣는다. 사용자가 즉시 재도전을 고를 때만 같은 세션에서 반복한다.
4. 장기 기억용 간격 반복은 별도 `암기 유지` 모드에서 선택한다. 짧은 간격이나 시간 알림을 기본값으로 강제하지 않는다.
5. 각 카드에는 원본 PDF의 Drive 파일 ID, Ravil 보관본 버전, 페이지와 근거 텍스트/이미지 위치를 남긴다. 새 Goodnotes 판본이 들어오면 이전 판본 카드에 `원본 변경됨`을 표시하고 재검토 전에는 새 판본의 사실인 것처럼 재사용하지 않는다.

Anki 앱은 실행됐으나 Computer Use가 `failedToCreateImageDestination`를 반환해 화면과 실제 사용자 설정을 캡처·검토하지 못했다. 따라서 Anki 화면 감사가 끝났다고 주장하지 않는다. 위 Anki 동작 근거는 [Anki 학습 단계](https://docs.ankiweb.net/deck-options.html)와 [필터 덱/시험 전 학습](https://docs.ankiweb.net/filtered-decks.html)의 공식 문서다.

## Codex 연결: Ravil 안의 클라이언트

2026-09-25 사용자 정정: 원하는 것은 **Codex에 Ravil 검색 도구를 붙이는 역방향 연동이 아니라**, VS Code의 Codex 확장처럼 Ravil 앱 내부에 Codex 대화·승인·문맥 연결 UI를 두는 것이다. 이 방향을 기본안으로 확정한다. 이전의 MCP 서버 제안은 선택적인 보조 연동으로만 남긴다.

[공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)는 App Server가 VS Code 확장 같은 풍부한 클라이언트에 쓰이고 인증, 대화 이력, 승인, 스트리밍 이벤트를 제공한다고 명시한다. 따라서 Ravil의 Mac 앱은 Codex VS Code 확장을 화면에 붙여 넣는 것이 아니라, 로컬 App Server를 연결해 자체 SwiftUI 패널을 만드는 방향이 맞다. 자동화용 [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)는 이 대화형 클라이언트의 첫 선택이 아니다.

예상 사용자 흐름:

1. Ravil의 `Codex` 패널에서 `ChatGPT로 연결`을 누른다. App Server가 관리하는 공식 로그인 흐름을 사용하고 Ravil은 계정 비밀번호·토큰을 자체 DB에 복사하지 않는다.
2. 사용자가 현재 보고 있는 과목, 선택한 Goodnotes PDF의 **현재 판본과 선택 페이지**, Alt 강의의 해당 전사 구간을 명시적으로 문맥에 추가한다. 전체 Ravil DB나 폴더 전체를 자동 전송하지 않는다.
3. Ravil 안에서 질문·답변을 스트리밍으로 표시하고 대화 이력을 이어 간다. 답변의 근거는 Ravil 자료 ID/버전/페이지로 다시 열 수 있게 한다.
4. Codex가 노트·퀴즈를 새로 저장하거나 기존 자료를 바꾸려는 경우에는 변경 내용을 먼저 보여 주고 사용자 승인을 받아야 한다. 초기 단계는 읽기 전용으로 시작한다.
5. 로그인 실패, 한도 초과, 서버 종료, 자료 판본 변경을 각각 분리해 표시한다. 로컬 자료와 사용자의 메모는 실패해도 보존한다.

App Server는 [ChatGPT 관리형 로그인과 계정/플랜·한도 조회](https://learn.chatgpt.com/docs/app-server)를 지원한다. 그러므로 개인용 Ravil에서는 우선 사용자가 자신의 Codex 로그인으로 연결하는 경험을 검증한다. [Codex 요금 안내](https://learn.chatgpt.com/docs/pricing)는 구독 경로와 API 키 과금 경로를 구분한다. Ravil 앱 자체의 유료 구독을 다른 사용자에게 판매하는 일은 **별도 제품·과금 결정**이며, 개인의 ChatGPT 구독을 Ravil 공용 서버 API 키처럼 돌리는 구조로 가정하지 않는다.

이 Mac에서는 `codex-cli 0.150.0` 실행 파일과 `codex app-server --help` 명령이 확인됐다. 이는 로컬 런타임이 설치돼 있다는 확인일 뿐, Ravil에서의 로그인·대화·자료 문맥 전달이 동작한다는 검증은 아니다.

현재 중간고사 PDF에는 학교·선생님 자료와 개인 필기가 있다. 외부 모델에 보내는 범위와 승인 UI를 먼저 만들기 전에는 클라우드 호출을 켜지 않는다. 이 문서는 연결 설계이며 App Server 로그인·실제 대화는 아직 구현·검증되지 않았다.

## 아직 결정할 것

- 개인 Mac의 Codex 연결을 먼저 검증한 뒤 다른 사용자도 가입하는 Ravil 구독 서비스로 확장할지.
- 자동 퀴즈의 근거로 OCR까지 완료된 페이지만 허용할지, 텍스트층이 없는 자료를 이미지 분석으로 처리할지.
- 시험 범위·시험 날짜와 과목별 중요도를 어떻게 입력하거나 검증할지.
