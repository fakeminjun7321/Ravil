# Ravil-ASMR 0.4 개발·검증 기록

2026-09-30. 우선 지원 범위는 한국어, 영어, 한영 혼용이다. 사용자는 Alt의 모든 녹음과 기존 학습지를 학습·평가에 사용할 수 있다고 밝혔다. 이번 변경은 **동일한 Qwen 가중치의 전사 처리 개선**이며 추가 학습이나 새 가중치 출시가 아니다. 출처·고정 리비전·파일 해시는 [모델 카드](../config/ravil-asmr-0.4-MODEL_CARD.md)에 있다.

## 발견한 문제와 구현

0.3은 5분 이하 파일 전체를 `max_tokens=512` 한 번으로 처리했다. 약 4분짜리 낭독 음성에서도 출력 한도에 도달했지만 완료된 전사처럼 저장될 수 있었다. 한 언어를 전체 파일에 지정하는 방식도 한국어와 영어가 번갈아 나오는 자료에서 문장 누락을 보였다.

`script/ravil_asr_longform.py`와 `script/transcribe_mlx_qwen_longform.py`는 다음을 추가한다.

- 최대 30초의 구간마다 독립적으로 언어 판단과 출력 예산을 사용한다. 기본값은 자동 판단이며 한국어·영어 지정도 가능하다.
- 양쪽 최대 1초를 함께 듣고, 정렬된 단어의 중간 시각이 속한 구간에서 그 단어를 보관한다. 반복해서 실제로 말한 단어를 문자열 중복 제거로 지우지 않는다.
- 전체 원본 구간을 빠짐없이 처리한다. 완전히 0인 디지털 무음만 생략하며, 조용한 발화는 음량 기준으로 삭제하지 않는다.
- 출력 한도 도달 또는 유효하지 않은 단어 시각은 더 작은 구간으로 최대 3단계 재처리한다. 해결되지 않으면 오류로 종료하고 완성 전사 파일을 만들지 않는다.
- 짧은 발화에서 지원 범위 밖의 언어가 감지되면, 양쪽 문맥을 4초로 늘려 한 번만 다시 인식한다. 여전히 해결되지 않으면 해당 시점을 명시하고 종료한다. 언어를 임의로 강제해 번역하지 않는다.
- 옵션으로 Silero VAD의 발화 사이를 분할 지점으로 사용한다. VAD가 음성으로 분류하지 않은 샘플도 그대로 보존한다. 30초 이하 자료에는 이 옵션의 분할을 적용하지 않는다.
- 로컬 출력은 0600 권한이며 기존 파일을 덮어쓰지 않는다. 입력 SHA-256, 모델 출처, 실행 설정과 처리 구간을 함께 기록한다.
- 비무음 구간에 정렬된 단어가 없으면 `reviewRequiredRanges`로 표시한다. 이때 파일은 `status: needs_review`로 저장하며 CLI 종료 코드는 3이다. 소비자는 JSON 디코딩 성공과 별도로 이 상태를 확인해야 한다.

단순히 RMS 음량이 낮은 곳마다 자르는 중간 실험은 영어 오류를 늘려 채택하지 않았다. Silero 역시 모든 조건에서 이득이 아니므로 기본으로 강제하지 않는다.

## 공개 음성을 이어 붙인 진단 시험

Google FLEURS의 한국어·영어 test 음성을 PCM16으로 변환하고, 각 원본 사이에 0.5초 무음을 붙였다. 각 파일은 229–233초다. 자연스러운 교실 녹음이나 한 문장 안의 언어 전환을 대표하지 않는다. **이 세 파일은 개발 중 비교에 사용한 진단 자료**이며 일반화 성능을 주장하는 독립 시험이 아니다.

같은 6비트 ASR·4비트 정렬 가중치와 같은 Mac M5에서 측정했다. 한국어·혼용은 공백·문장부호·대소문자를 정규화한 CER, 영어는 정규화한 WER다. 서로 다른 지표의 언어 간 순위를 매기지 않는다.

| 조건 | 0.3 전체 파일 처리 | 0.4 기본 분할 | 0.4 + VAD 분할·정렬 재시도 |
|---|---:|---:|---:|
| 한국어 730자 | 167 오류 / 22.88% | 6 / 0.82% | 6 / 0.82% |
| 영어 479단어 | 85 오류 / 17.75% | 22 / 4.59% | 44 / 9.19% |
| 한영 전환 1,353자 | 948 오류 / 70.07% | 464 / 34.29% | 40 / 2.96% |

0.3은 한국어·영어 파일에서 모두 512토큰 한도에 도달했다. 혼용은 기존 CLI에 auto 모드가 없어 한국어 지정으로 비교했다. 따라서 이 수치는 기반 Qwen 모델 자체의 한계를 나타내는 수치가 아니라, Ravil의 이전 설정과 새 처리 경로의 차이다.

기본 분할의 한국어/영어 처리 시간은 14.37/14.24초, 비교 실행의 0.3은 14.13/13.38초였다. 최대 활성 MLX 메모리는 약 5.54–5.59GB에서 4.23GB로 감소했다. VAD 옵션은 혼용에서 약 18.08초와 4.02GB를 사용했다. 추가 검출기의 CPU 메모리와 에너지 사용을 포함한 전체 시스템 메모리·배터리 벤치마크는 아니다.

짧은 음성은 한국어 20문장 CER 9/895 = 1.01%, 영어 20문장 WER 24/462 = 5.19%로 이전 방식과 동일했다. 한국어 띄어쓰기 기반 WER는 11/286에서 13/286으로 달라졌으므로 모든 문자·공백이 동일하다는 뜻은 아니다.

실험 원본:

- `tmp/model-opt/longform-eval-v1/report.json`: 기본 분할, 긴 파일 3개 및 짧은 음성 40개.
- `tmp/model-opt/longform-eval-v2/report.json`: 채택하지 않은 RMS 조기 분할 실험.
- `tmp/model-opt/longform-eval-v3/report.json`: VAD 분할. 혼용 정렬 오류를 발견한 실행이며 완전 통과로 취급하지 않는다.
- `tmp/model-opt/longform-eval-v4-mixed/report.json`: 해당 오류의 제한된 구간 재처리를 구현한 후 혼용 재검증.

### 별도 음성으로 확인

설정 변경에 사용한 자료와 원본 ID가 겹치지 않는 별도 음성을 같은 방식으로 연결했다. 준비한 전체 확인 자료의 원본 40개와 개발 자료의 원본 38개 사이에 겹치는 ID는 0개였다. 이 중 **235.28초 한영 전환 파일 한 개**를 평가했다. 확인용 한국어·영어 단독 파일은 준비만 했고 추가 평가하지 않았다.

해당 파일은 이전 방식 1,277/1,634자 오류(78.15%), 새 VAD 분할 경로 143/1,634자 오류(8.75%)였다. 전처리·전사·정렬을 포함한 측정 구간은 13.872초 → 17.501초, 최대 활성 MLX 메모리는 약 5.61GB → 4.09GB다. 여전히 구성된 낭독 음성이며 자연스러운 수업의 정확도라고 해석하지 않는다. 기록: `tmp/model-opt/longform-confirmation-v1/report.json`.

## 로컬 실행과 검증 수준

**Implemented:** 오프라인 긴 녹음 CLI, 구간별 언어 처리, 제한된 재시도, 출처 기록이 존재한다.

**Unit-verified:** `test/test_asr_longform.py`의 15개 검사가 통과했다. 오디오 구간의 빈틈 없는 연결, 경계 단어의 소유권, 실제 반복 단어 보존, 토큰 한도와 정렬 오류 재시도, 언어 판별의 제한된 문맥 재시도, 비무음 빈 구간의 검수 표시, 디지털 무음, 잘린 WAV, VAD 센티초 변환과 결과 개수 검사를 포함한다. 이 검사의 모델은 가짜 구현이므로 음성인식 정확도를 증명하지 않는다.

**실제 Mac CLI 경로 검증:** 사용자 허가된 물리 수업 420초를 네트워크 차단 상태에서 처리했다. 전사 34.228초, 정렬 5.909초, 모델 로드 0.980초, 최대 활성 MLX 메모리 약 4.14GB. 71개 구간이 파일에 저장됐고, 격리된 Ravil 실행 파일의 실제 `WhisperOutput` 디코더가 다시 읽었다. 출력 파일은 `tmp/model-opt/private-longform-v1/` 아래에 비공개로 보관한다. 이 실행은 사람 정답과 대조한 정확도 검증이 아니다.

영어 **과목** 녹음 전체 690.408초도 네트워크 차단 상태에서 VAD 분할로 처리하고 129개 전사 구간을 저장·재읽기했다. 전사 52.983초, 정렬 8.672초, 로드 1.272초, 최대 활성 MLX 메모리 약 4.23GB였다. 169.105–174.160초 구간이 처음에는 포르투갈어로 감지됐고, 문맥 확대를 구현한 뒤 이 구간을 통과했다. 전체 실행에서 문맥 재시도는 2회였다.

이 VAD 실행의 사후 검사에서 **245.620–252.210초와 324.580–331.470초는 정렬된 단어가 0개**였다. 두 구간이 실제 무음인지 발화 누락인지는 사람 검수가 필요하다. 따라서 영어 과목 전체의 정확한 전사가 완료됐다고 판정하지 않는다. 원본 실행 파일은 유지하고 `english-0.4-quality-audit.json`에 `needs_review`를 기록했다. 이 발견 이후 CLI에는 위의 검수 상태와 종료 코드 3을 추가했다.

같은 690.408초 원본을 **기본 분할(VAD 없음, 구간별 언어 자동 판단)**로 다시 확인했다. 전사 45.158초 + 정렬 6.288초, 로드 0.952초, 최대 활성 MLX 메모리 약 4.23GB였다. 26개 처리 구간에서 125개 전사 구간을 저장했고, 비무음인데 정렬 단어가 없는 구간은 0개, 언어 문맥 재시도도 0회였다. 출력의 `status: transcribed`, 입력 파일 해시, 연속된 처리 범위, 시각 범위, 0600 권한 및 Ravil 디코더 재읽기를 확인했다. 기록은 `english-0.4-default.json`과 `english-0.4-default-metrics.json`이다. 이 역시 내용 정확도의 사람 검수를 대신하지 않는다.

**이번 기본값은 VAD를 사용하지 않는 분할 방식으로 유지한다.** VAD는 구성된 한영 전환 시험에서 큰 효과가 있었지만 영어 단독 및 실제 녹음에서 항상 우세하지 않았다. 옵션 선택을 자동화하려면 더 많은 교정된 수업 정답이 필요하다.

**Not verified / 미검증:** 설치 앱의 녹음 버튼→전사→DB 저장→재열기, 자연 수업의 검수된 CER/WER·단어 시각, 화자 분리, 다른 Mac 설치, 배터리, 공개 가중치 배포. 앱 기본 모델이나 배포 DMG를 교체하지 않았다.

## 재현

개발용 가상환경은 `config/model-opt-requirements.txt`를 사용한다. 공개 평가 준비에는 `ffmpeg`도 필요하다. 모델과 VAD는 모델 카드에 적힌 해시가 일치해야 한다.

```sh
tmp/model-opt/venv/bin/python -m unittest discover -s test -p 'test_asr_longform.py'

tmp/model-opt/venv/bin/python script/transcribe_mlx_qwen_longform.py \
  --audio /absolute/path/to/mono-16k-pcm16.wav \
  --asr-model tmp/model-opt/models/qwen3-asr-1.7b-6bit \
  --aligner-model tmp/model-opt/models/qwen3-aligner-0.6b-4bit \
  --language auto \
  --output /absolute/path/to/new-transcript.json \
  --metrics /absolute/path/to/new-metrics.json
```

혼용 자료의 VAD 실험에는 `--vad-engine tmp/model-opt/whisper-build/bin/whisper-vad-speech-segments --vad-model tmp/model-opt/models/ggml-silero-v6.2.0.bin`를 추가한다. 해당 바이너리는 고정된 whisper.cpp 소스의 별도 개발 빌드다. 설치 앱의 배포 런타임에 포함됐다는 뜻은 아니다.

다음 가중치 학습에서는 Alt 전사를 그대로 정답으로 취급하지 않는다. 허가된 전체 녹음에서 강의 단위로 학습·평가를 분리하고, 한국어·영어·혼용의 교정된 정답을 확보한 뒤 고유한 어댑터 학습 효과를 측정한다.
