# RAVIL: 개인용 세컨드 브레인 디자인 조사

조사일: 2026-10-19. 공식 소개·제품·기능 페이지와 공개 시연 화면을 직접 확인했다. 계정 가입, 유료 앱 로그인, 실제 개인 자료 업로드는 하지 않았다. 아래 관찰은 제품의 실제 성능이나 사용성 실험 결과가 아니다.

## 이번 작업 기준

사용자는 과거 디자인의 단순 복원 대신 제품 목표에 맞는 재디자인을 요청했고, 비슷한 목표를 가진 제품을 충분히 조사한 뒤 디자인하라고 정정했다. 작은 글씨와 성숙한 입력 방식, Mac의 Codex·로컬 모델 연결 요청을 유지한다. 기존 3번 시안은 새 디자인의 확정 기준으로 사용하지 않는다.

현재 제품 목표는 [product-goal.md](/Users/minjun/Ravil/docs/product-goal.md)를 따른다.

> 내가 자유롭게 남긴 기록을 AI가 분석하고 정리하며, 필요한 순간에 생각과 행동을 돕는 개인용 세컨드 브레인 워크스페이스.

학업, 일상, 경험, 아이디어, 의사결정, 개인 프로젝트는 모두 활용 사례다. 과목·시험·마감일을 기록의 필수 조건으로 만들지 않는다.

## 공통으로 확인한 것

관찰: 소개 페이지에는 큰 타이틀과 강한 그래픽이 자주 쓰이지만, 공개된 작업 화면은 더 작은 도구·차분한 본문·지속적인 탐색 구조를 사용한다. RAVIL은 두 화면의 역할을 구분해야 한다. 소개 페이지의 시각 효과만 빌려오면 개인 작업 공간의 사용 흐름이 드러나지 않는다.

설계 판단: 제품 성격은 **Mem의 입력/정리 흐름 + Capacities의 연결 구조**를 중심에 둔다. 글쓰기 조판은 Craft·Reflect, 계획 표현은 Sunsama를 참고한다. 여러 제품의 색·그림자·카드를 단순 합성하는 방향은 택하지 않는다.

## RAVIL에 적용할 설계 기준

1. **분류보다 입력이 먼저다.** 오늘의 기록, 짧은 메모, 사진/PDF를 먼저 남긴다. 주제와 프로젝트는 선택하거나 AI 제안을 보고 연결한다.
2. **원문이 중앙이다.** 목록과 원문이 기본 화면이며 AI 맥락 패널은 필요할 때 연다. 채팅 자체가 기록을 대체하지 않는다.
3. **AI가 한 일을 구분한다.** 요약, 관련 기록, 질문 답변, 다음 행동을 구분하고 각각의 출처로 이동할 수 있게 한다. 기록이 바뀌면 예전 분석임을 표시한다.
4. **다시 찾기가 눈에 띈다.** 공통 검색과 `⌘K`, 최근 기록, 연결된 주제/프로젝트를 일관된 위치에 둔다.
5. **계획은 기록에서 파생된다.** 마감이 없는 생각도 정상적인 기록이다. 날짜가 있는 다음 행동만 일정 배치로 이어진다.
6. **학습은 하나의 사례다.** 첫 화면의 사례는 일상 메모·관심사·개인 프로젝트·책/경험·학습이 섞여 있어야 한다.
7. **모델 선택은 도움받는 방식이다.** Mac에서 Codex·Ollama·LM Studio를 연결하되 현재 대상 기록과 사용 모델이 분명해야 한다. 다른 앱/전체 파일의 자동 관찰을 전제하지 않는다.
8. **개인 작업 도구의 밀도를 유지한다.** 큰 설명 문장, 배지, 숫자 카드의 반복을 줄인다. `/` 입력과 아이콘에는 툴팁·키보드 접근·메뉴 경로를 둔다.

## 다음 시안의 구성 기준

### 소개

- 적당한 크기의 목적 설명과 실제 기록→정리→활용 예시를 함께 보여준다.
- ‘내 기록을 남긴다’와 ‘이전에 남긴 기록에서 도움받는다’가 모두 보여야 한다.
- 단순한 AI 대화 서비스나 시험 전용 학습 앱처럼 소개하지 않는다.

### 작업 공간

- 좌측: 오늘 / 기록함 / 주제·프로젝트 / 보관. 폴더 이동보다 기록 접근을 우선한다.
- 중앙: 제목을 꼭 정하지 않아도 쓰기 시작할 수 있는 원문 편집기와 자료.
- 필요할 때 여는 맥락 패널: 정리 / 연결된 기록 / 질문 / 다음 행동. AI 근거와 적용 여부를 표시한다.
- 계획은 별도 보기와 선택적 시간축에서 다룬다. 원문 연결은 계속 유지한다.

### 글씨 크기 제안

아래 수치는 타 사이트에서 측정한 값이 아니라 RAVIL의 다음 시안 기준 제안이다.

- 작업 UI: 12–13px, 문서 제목: 26–30px, 본문: 데스크톱 15–16px.
- 모바일 입력 본문: 16px 이상을 유지하고 메뉴·메타데이터의 밀도로 전체 크기를 줄인다.
- 소개 제목: 36–44px 범위에서 한글 줄바꿈을 확인한다. 장식보다 기록 예시가 먼저 이해되어야 한다.

색상과 구체적인 최종 배치는 아직 확정하지 않았다. 다음 시안에서 실제 한글 기록으로 검토한다.

## 조사 근거와 범위

- 공식 사이트 7개와 추가 제품/기능 자료를 확인했다.
- 공개 시연의 제한된 조작: Mem 비교 슬라이더, Tana Tasks/Projects 전환, 제품 내비게이션. Sunsama는 선택 쿠키를 거절한 후 확인했다.
- [출처와 캡처 목록](sources.json)에 페이지 URL, 화면 성격, 해시를 저장했다. 제3자 캡처는 내부 조사 자료이며 RAVIL의 실제 화면/생산 자산으로 배포하지 않는다.
- 이번 연구 단계에서 RAVIL 운영 사이트 요청·배포·새 UI 소스 교체는 수행하지 않았다.
- Codex·로컬 모델 연결과 원문/근거 기반 AI 결과 UI는 이어갈 구현 범위다. 이 문서 자체가 그 기능의 구현/검증 증거는 아니다.


## 선택 이후 구현

사용자가 1번 원문 + AI 맥락 패널을 선택했다. 소개·계정·작업 화면을 같은 체계로 구현했으며, 선택 시안의 역할 분리와 여백을 유지하면서 실제 UI의 글씨 크기는 위의 축소 기준을 적용했다. 브라우저의 제공자는 실제 연결 경로인 RAVIL AI로 표시하고 Codex·로컬 모델 선택은 Mac에 구현했다.

최종 구현 화면과 로컬 검증 자료는 [implemented/](implemented/)에 있다. 상세 범위와 미검증 항목은 [개발 기록](../../../../docs/design-and-connections-2026-10-19.md)을 따른다. 구현 화면은 HTML·CSS와 실제 편집기로 만들었으며 시안 이미지를 작동하는 화면처럼 배치하지 않았다. 운영 배포는 수행하지 않았다.
